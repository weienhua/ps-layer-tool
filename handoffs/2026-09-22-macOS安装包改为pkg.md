## 关键决策

- **用 Apple Installer `.pkg`，而不是 vercel/pkg 二进制**：`pkgbuild`/`productbuild` 是 macOS 自带工具链，载荷是纯 JS/HTML、与架构无关；vercel/pkg 已归档、无 arm64 目标、未签名会被 Gatekeeper 拦
- **完全替换 `.sh`/`.command`**（用户选择）：旧方案传到新电脑会丢执行位，用户需 `chmod` 才能装；`.pkg` 双击即装。代价是未签名 `.pkg` 仍会被 Gatekeeper 拦截（见注意事项）
- **两个包（安装 + 卸载）**：`.pkg` 的 payload 只能新增/覆盖文件、**无法删除文件**，删除必须靠脚本，所以卸载是第二个带 `postinstall` 的无载荷包（对应 Windows 的两个 exe）
- **用户域安装（`enable_currentUserHome` only）**：装到 `~/Library/…` 且文件属主是用户。**装系统域 `/Library` 会因 root 属主导致面板无法写 `dist/lib/presets/*/default.json`** —— 硬约束，已写进 distribution 与验证断言
- **单个确定性备份目录复用**：`preinstall` 的覆盖安装备份与卸载备份共用 `${EXTENSION_ID}_user_files`（`BACKUP_DIR`）。`preinstall`/`postinstall` 是独立进程、无法传状态，「用户原先有没有预设」由 `$BACKUP_DIR/presets` 是否存在推导；备份目录布局与 Windows `scripts/install.js`/`uninstall.js` 一致，跨平台互通
- **`common.sh` 构建时内联 + 函数式 replace**：三个脚本共用同一份逻辑；渲染必须用函数式 `replace`，否则 `common.sh` 里的 `$1` 会被当成替换模式
- **`<welcome>` 而非 `<readme>` + `rootVolumeOnly="true"`**：前者去掉介绍页的「打印/存储」，后者去掉「更改安装位置」入口（沿用参考项目已实机确认的结论）
- **默认不签名，只留开关**：`MACOS_INSTALLER_IDENTITY` 有值才 `productsign`；未签名时 Gatekeeper 拦截属预期，文档给了三条绕行路径

## 已知问题 / 注意事项

- **验证口径修正**：**vercel/pkg 产物本身非确定性**（同一 `dist`、同一脚本连跑两次，文件尺寸相同但注入尾部有 598 字节差异）。所以「exe 字节一致」不能作为回归判据，改用「同 dist 下原脚本 vs 新脚本尺寸一致 + 差异仅落在尾部注入区」
- **`buildZip()` 用 `zip -r` 更新已有归档**（HEAD 既有行为，本轮未改）：本地重复打包时，上一轮存在、这一轮已删除的文件（如 `dist/bundle.js.map`）会**残留在 zip 里**。CI 从干净目录构建不受影响。最小修法是在 `zip` 前删掉旧 zip
- **`dist/lib/presets/` 会被打进 payload**：它是运行时用户数据（webpack 不复制、`git ls-files` 无 `dist`），开发机上存在、CI 上不存在。目前靠 postinstall 的「用户原先无预设 → 删除包内 presets」兜住，与 `.sh`/Windows 语义一致；若要更干净可在打包时把它从 payload 中剔除（参考项目是把它当内置种子，本项目不是）
- **未签名 `.pkg` ≠ 免 Gatekeeper**：消除的是 chmod，不是 Gatekeeper。要零提示必须 Developer ID 签名 + 公证（$99/年，本轮按用户选择不做）
- **Installer 自带的「安装」按钮与步骤名改不了**：来自系统本地化；卸载包只能靠 `<welcome>`/`<conclusion>`/标题表达「卸载」语义
- **XML 注释里不能出现连续两个连字符**：写 `--nopayload` 会让 `productbuild` 直接报 `Comment must not contain '--'`
- **开发机的坑**：若本机 `~/Library/Application Support/Adobe/CEP/extensions/com.layertool.panel` 是**符号链接**，双击安装会先 `unlink` 再写真实文件（源目录不受影响，但开发工作流会被替换）——真机测试建议另建测试账号
- **沙箱里跑 `npm run package` 需要 `PKG_CACHE_PATH` 垫片**（vercel/pkg 写 `~/.pkg-cache` 被拒）：`mkdir -p /tmp/dsh-pkg-cache/v3.4 && ln -sf ~/.pkg-cache/v3.4/fetched-v18.5.0-win-x64 /tmp/dsh-pkg-cache/v3.4/ && PKG_CACHE_PATH=/tmp/dsh-pkg-cache npm run package`，完事删掉 `/tmp/dsh-pkg-cache`
- **验证脚本的测试通道**：`PS_LT_TEST_HOME` / `PS_LT_TEST_USER` 是**仅测试**的用户目录覆盖（生产 Installer 不会设置）；演练用 PATH 垫片拦截 `defaults`，避免写真实用户域
- **`pkgutil --expand-full` 才有解出真实 payload**（`--expand` 只留原始压缩包）；它没写进 man page 但可用
